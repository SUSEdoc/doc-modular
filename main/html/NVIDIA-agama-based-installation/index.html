AMD64/Intel 64: Installing SLE for NVIDIA Manually Using Agama

Publication Date: 02 Nov 2026

Agama is SUSE's open source installer for SUSE Linux Enterprise Server for NVIDIA 16.1 and later versions. Use Agama to manually install the product on bare-metal servers and virtual machines. Agama provides an intuitive, flexible interface for installing ready-to-use system images and simplifies the configuration of your system during deployment.

Prerequisites

  • A bare-metal server or virtual machine with a minimum of 1 CPU, 2 GB memory and 32 GB storage

  • An Agama-based ISO image file of SUSE Linux Enterprise Server for NVIDIA

  • An active registration code for SUSE Linux Enterprise Server for NVIDIA from the SUSE Customer Center

Revision History: AMD64/Intel 64: Installing SLE for NVIDIA Manually Using Agama

1 Introduction to Agama #

 

This section provides a short overview of Agama, which is the default installer for SUSE Linux Enterprise Server for NVIDIA 16.1 and later versions.

Agama is a flexible and powerful open source installer developed by SUSE. You can use it to perform manual or automated installation of supported SUSE Linux Enterprise Server for NVIDIA versions on a variety of machine architectures. The Agama‐based installation method provides an intuitive interface for ready‐to‐use images for different use cases and workloads. In combination with Cockpit and Ansible, it substitutes YaST in SUSE Linux Enterprise Server for NVIDIA.

2 System requirements #

 

The installation needs the following minimum resources for SUSE Linux Enterprise Server for NVIDIA. This section also lists recommendations for specific uses.

Minimum system requirements for installation #
 
CPU

AMD64 or Intel 64, micro architecture level x86-64-v2 or higher

Memory

1024 MiB RAM

512 MiB Swap recommended

Hard disk

2 GiB available disk space (more recommended, 8.5 GiB for all patterns) 32 GiB for snapshot/rollback of the OS

Recommendations for specific uses #
 

  • 1 GiB to 8 GiB RAM, at least 512 MiB per CPU

  • 8 GiB hard-disk space, 32 GiB for snapshot/rollback of the OS

  • For print servers: a faster processor or additional processors to improve server-based printing

  • For Web servers: additional RAM to improve caching and additional processors to improve Web application performance

  • For database servers: additional RAM to improve caching and multiple disks for parallel I/O

  • For file servers: additional memory and disks, or a RAID system, to improve I/O throughput

  • For SAP applications: additional memory and disks as recommended by SAP

3 Booting the Agama installer #

 

The first step in the installation is booting the Agama installer.

Procedure 1: Booting the Agama installer #
 

  1. Select a bootable media and start the installation process.

    • For a bare-metal server, select the device or storage volume from which to boot.

    • For a virtual machine guest, select the path to the image file. Configure the virtual machine for the expected workload.

  2. In the GRUB 2 boot menu, select Install SUSE SLE 16.1 (x86_64).

6 Registering the system #

 

Register the product in the Registration screen.

6.1 Registering extensions #

 

After successfully registering the base system, you can register additional extensions. The following extensions are available for SUSE Linux Enterprise Server for NVIDIA 16.1:

Extensions for the SUSE Linux Enterprise Server for NVIDIA 16.1 family #
 
SUSE Linux Enterprise High Availability Extension 16.1

The SUSE Linux Enterprise High Availability extension provides mature, industry-leading open source high-availability clustering technologies that are easy to set up and use. You can deploy it in physical environments, virtual environments or both. It clusters physical servers, virtual servers or any combination of the two to suit the needs of your business.

To register your SUSE Linux Enterprise High Availability extension, enter its registration code and click Register.

SUSE Package Hub 16.1

SUSE Package Hub is a free module providing access to community-maintained packages built to run on SUSE Linux Enterprise Server for NVIDIA. Built from the same sources used in openSUSE distributions, these quality packages provide additional software to what is found in SUSE Linux Enterprise Server for NVIDIA. The packages in this module are delivered without L3 support but do not interfere with the supportability of SUSE Linux Enterprise Server for NVIDIA.

To register with the SUSE Package Hub, click Register. When the installer asks whether to trust the signing key of the SUSE Package Hub repository, click Trust.

7 Configuring the system #

 

In the System screen, configure the host name and the time synchronization servers.

Figure 5: Agama installer system settings #
 

7.1 Setting the host name #

 

Set the host name of the system in one of the following modes.

Host name setting modes #
 
Transient (default)

The host name is assigned with DHCP and may change after a reboot or network change. The transient host name agama is used for the installation.

Static

Set a static host name. You can either use a fully qualified domain name (FQDN) or the host name part only.

Important: Host name for the registration

The host name is used for the registration with the SUSE Customer Center. If you do not set a host name, your system will be registered with the transient host name agama. Even if the system is assigned a new host name later, it will not automatically get updated in the SUSE Customer Center. Therefore setting host name is recommended.

To update the host name in the SUSE Customer Center after registration, first change the system's host name. Then use SUSEConnect to deregister the system and register it again under the new host name.

Tip: Identifying systems in the SUSE Customer Center

If you have multiple systems registered with the same host name in the SUSE Customer Center, it is difficult to tell them apart. To identify a system, use its UUID. You can find it under Hardware information in the SUSE Customer Center and on the system by running dmidecode -s system-uuid.

7.2 Setting time synchronization servers #

 

The system time is set with the Network Time Protocol (NTP) to ensure the system time is always correct. Choose one of the following modes:

Time synchronization modes #
 
Default

The system uses one of the default SUSE NTP servers 1.suse.pool.ntp.org to 3.suse.pool.ntp.org. If your system is behind a firewall, make sure that these servers are reachable from your network.

Custom

In the custom mode, you can configure the NTP servers to use. Use this option for air-gapped environments. Specify servers by host name, IP address or FQDN. Separate multiple entries with colons.

Click Accept to save your changes.

Bonding settings #
 
Name

Name of the connection. Meaningful names can use the destination (Internet), the connection type (Bond) or the device (bond0, if device binding is enabled). Free text, but for practical reasons it is recommended to avoid special characters.

Device name

Provide a device name such as bond0.

Bond mode

Select the bonding mode:

balance-rr

Packets are transmitted in round-robin fashion from the first to the last available interface. Provides fault tolerance and load balancing. Requires switch support. Certain switches might fail with this mode.

active backup

Only one network interface is active. If it fails, a different interface becomes active. Provides fault tolerance. No specific switch support is required.

balance-xor

Traffic is split between all available interfaces based on the number of interfaces included in the bonded device. Provides fault tolerance and load balancing. Requires switch support. Certain switches might fail with this mode.

broadcast

All traffic is broadcast on all interfaces. Provides fault tolerance. Requires switch support. Certain switches might fail with this mode.

802.3ad

Also called LACP. All interfaces in the LACP group must share the same speed and duplex settings, and must be connected to the same switch. Provides fault tolerance and load balancing. Requires ethtool support in the interface drivers, and a switch that supports and is configured for IEEE 802.3ad Dynamic link aggregation. If your switch supports it, this is the preferred mode.

balance-tlb

Adaptive transmit load balancing. Provides fault tolerance and load balancing. Requires ethtool support in the interface drivers. No specific switch support is required, but certain switches might fail with this mode.

balance-alb

Adaptive load balancing. Provides fault tolerance and load balancing. Requires ethtool support in the interface drivers. No specific switch support is required, but certain switches might fail with this mode.

11 Configuring storage #

 

Select a storage device for the installation in the Storage screen.

Figure 9: Agama installer storage configuration #
 

Currently installations on single discs or LVM are supported. To change the disk or use LVM, click the device name More options button in the Installation devices section.

To detect an iSCSI disk, select the iSCSI initiator and click Discover iSCSI targets.

By default, the file systems are allocated as new partitions on the selected device. You can change this behavior in the drop-down list labeled All content will be deleted in the Installation devices section. The following space policies are available:

Space policies #
 
Delete current content

All partitions are removed, and any data on the disks is lost.

Shrink existing partitions

The data is kept, but Agama shrinks the current partitions as needed.

Use available space

The data is kept. Only the space not assigned to any partition is used.

Custom

Select what to do with each partition.

Important: RAID support

The current Agama user interface does not expose all the options supported by Agama's storage configuration. Complex configurations such as RAID can be applied through Agama profiles. For more information, refer to the article Automated Installation Using Agama.

If the selected storage already has a RAID configuration —either from a previous installation or created by an Agama profile—the RAID devices can be used for installation. In this case, you may see a message like Use RAID 0 (60.00 GiB) to host LVM in the user interface. Please note in this context, the term RAID 0 refers to the RAID device (/dev/md/0), not the RAID level.

To edit individual partitions, expand the Partitions and file systems section by clicking >. Optionally, you can configure Btrfs snapshots, boot options and enable full disk encryption (FDE).

12 Configuring authentication #

 

Before you continue, create an administrator account or configure authentication for the root user.

Figure 10: Agama installer authentication settings #
 

Before you can continue with the installation, you need to create an administrator account or configure the authentication for the root user.

12.1 Creating an administrator account #

 

To improve security, root login is disabled in SUSE Linux Enterprise Server for NVIDIA by default. Instead, an administrator user is used as main login account. This administrator can run administrative commands with sudo.

To create an administrator account, tick the checkbox Define an administrator user and enter the necessary user details.

Administrator user settings #
 
Full name

Full name of the administrator user.

Username

A user name. Only use lowercase letters (a-z), digits (0-9) and the characters . (dot), - (hyphen) and _ (underscore). Avoid other special characters and accented characters.

SSH Public Key (optional)

Paste one or more public SSH keys to enable passwordless login with SSH. To add a key, press Enter or →|. To remove a key, press <— or Del. To navigate between keys, use the ↑ and ↓ arrows.

Important: No SSH root access

SSH access for root is disabled by default. Therefore it is strongly recommended to create a system user. The first system user is granted sudo privileges automatically and can also be used for accessing Cockpit.

12.2 Configuring the root user #

 

Configure the authentication methods for the root. You can use a secure password, an SSH public key or both.

Figure 11: Agama installer root authentication configuration #
 
Root login method #
 
Disabled

The root login is disabled and the administrator uses sudo for all administrative tasks.

Password

The root can log in with a password. Configure a strong password.

SSH Public Key

The root can log in with an SSH public key. Paste one or more public SSH keys. To add a key, press Enter or →|. To remove a key, press <— or Del. To navigate between different keys, use the ↑ and ↓ arrows.

Password and SSH Public Key

The root user can log in both with a password and SSH key(s). Configure both as described above.
