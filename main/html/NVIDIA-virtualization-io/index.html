I/O Virtualization for Virtual Machines

Publication Date: 25 Nov 2026

I/O virtualization on SUSE Linux Enterprise Server for NVIDIA enables virtual machine guests to efficiently interact with physical hardware devices like network interfaces and storage controllers. By using paravirtualization, VFIO and SR-IOV techniques, I/O virtualization bypasses traditional software device emulation overhead. This significantly reduces latency and CPU consumption while delivering near-native hardware performance for resource-intensive virtualized workloads.

Prerequisites

  • IOMMU enabled in the BIOS/EFI

  • Intel IOMMU kernel parameter enabled for Intel CPUs

  • VFIO kernel module (vfio_pci) available for device pass-through

1 I/O virtualization #

 

In addition to CPU and memory, VM Guests share the VM Host Server's physical I/O subsystems such as network interfaces, storage controllers and GPUs. Because purely software-based I/O introduces latency and CPU overhead, SUSE Linux Enterprise Server for NVIDIA provides a choice of I/O virtualization techniques that trade off hardware compatibility against near-native performance:

Device emulation

The VM Host Server emulates well-known, legacy physical hardware, such as an Intel e1000 network adapter or an IDE/SATA disk controller. Because the virtualized device behaves identically to real hardware, the VM Guest can use its built-in operating system drivers without modification. However, every I/O operation must be intercepted and translated by the VM Host Server, causing significant CPU overhead and higher latency. Device emulation is primarily used for booting legacy operating systems or during initial OS installation before paravirtualized drivers are loaded.

Paravirtualized I/O

Instead of emulating physical hardware, paravirtualized I/O exposes a standardized, hypervisor-aware virtual device interface (virtio) directly to the VM Guest. The guest OS uses virtio drivers (included in Linux and available for Windows) to communicate efficiently with the VM Host Server via shared memory ring buffers. Combining virtio with kernel-space or user-space offloading (vhost/vhost-user) eliminates costly context switches, delivering high throughput and low latency while preserving live migration and full hardware independence.

Direct device assignment (VFIO)

Virtual Function I/O (VFIO) assigns an entire physical VM Host Server device (such as a PCIe NVMe drive, NIC or GPU) directly to a single VM Guest. Using the hardware IOMMU, VFIO isolates device memory access and allows the VM Guest's native vendor driver to interact directly with the hardware, completely bypassing the VM Host Server I/O stack. While VFIO delivers near-native performance, a passed-through device cannot be shared with the VM Host Server or other VM Guests, and live migration is generally unsupported.

Single Root I/O Virtualization (SR-IOV)

SR-IOV is a PCIe hardware standard that allows a single physical device to partition itself into multiple lightweight Virtual Functions (VFs). Each VF appears as an independent PCIe device that can be assigned directly to a separate VM Guest via VFIO. SR-IOV combines the near-native performance of direct device assignment with the ability to share a single physical device across multiple VM Guests. SR-IOV requires explicit support from the PCIe device, CPU/chipset, BIOS/EFI and host kernel.

Mediated devices (mdev/vGPU)

For devices that lack SR-IOV hardware partitioning, such as certain enterprise GPUs, the Linux mediated device framework allows a VM Host Server driver to split a single physical device into multiple software-defined virtual devices exposed through VFIO.

Important: Requirements for VFIO and SR-IOV

To be able to use the VFIO and SR-IOV features, the VM Host Server needs to fulfill the following requirements:

  • IOMMU needs to be enabled in the BIOS/EFI.

  • For Intel CPUs, the kernel parameter intel_iommu=on needs to be provided on the kernel command line.

  • The vfio_pci kernel module needs to be loaded.
